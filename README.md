# WLED Scanner
[![CI](https://github.com/StefanRiese/WLED_Scanner/actions/workflows/ci.yml/badge.svg)](https://github.com/StefanRiese/WLED_Scanner/actions/workflows/ci.yml)

<img src="./wled-scanner-rs/assets/icon.png" width="96" align="right" alt="WLED Scanner icon">

Finds [WLED](https://kno.wled.ge) devices on your local network. Runs on Windows, Linux and macOS.

The scanner finds devices in two ways:

- **mDNS** – every WLED device advertises the service `_wled._tcp`, so it is found without any
  configuration.
- **UDP broadcasts** on port **65506** – sent every 30 seconds by devices that have
  *Config → WiFi Setup / Sync Interfaces → Discover nodes* enabled.

Each device is queried via `http://<ip>/json/info` every 30 seconds; the list shows its name,
IP, version, architecture, uptime and when it was last seen. Devices that haven't answered or
announced themselves for more than 90 seconds stay in the list, greyed out. Select a device
and click **Open in browser** (or double-click it) to open its web UI.

> Your firewall must allow incoming UDP on ports 5353 (mDNS) and 65506. On macOS 15 and later,
> allow the "local network" access the app asks for on first start.

## Download

Prebuilt packages are attached to the [releases](https://github.com/StefanRiese/WLED_Scanner/releases):

| Platform | File |
|---|---|
| Windows | `wled-scanner-windows-x86_64.exe` |
| Linux | `wled-scanner-linux-x86_64.tar.gz` (binary, `.desktop` file and icon) |
| macOS (Apple Silicon + Intel) | `wled-scanner-macos-universal.zip` (`WLED Scanner.app`) |

The macOS app is not signed. On first start, right-click it and choose **Open**.

## Build from source

The app is written in Rust with [egui](https://github.com/emilk/egui) and lives in
[`wled-scanner-rs/`](wled-scanner-rs). Install Rust from <https://rustup.rs>, then:

```sh
cd wled-scanner-rs
cargo build --release
```

The binary ends up in `target/release/wled-scanner` (`wled-scanner.exe` on Windows).

Linux needs the usual X11/Wayland development packages, e.g. on Debian/Ubuntu:

```sh
sudo apt install libxkbcommon-dev libwayland-dev libgl1-mesa-dev libx11-dev
```

### App icon & packaging

The window/taskbar icon is compiled into the binary on all platforms. How the executable
itself gets its icon depends on the OS:

- **Windows** – the icon is embedded into `wled-scanner.exe` automatically by `build.rs`
  (shown in Explorer and the taskbar).
- **macOS** – executables get their icon from an app bundle. Build `WLED Scanner.app`:

  ```sh
  packaging/macos/make-app.sh              # current architecture
  packaging/macos/make-app.sh --universal  # Apple Silicon + Intel
  ```

- **Linux** – the icon comes from a desktop entry. Install binary, icon and `.desktop` file:

  ```sh
  packaging/linux/install.sh               # into ~/.local
  sudo packaging/linux/install.sh /usr/local
  ```

The icon files in `assets/` are generated by `assets/make_icon.py` (requires Pillow).

## CI & releases

GitHub Actions (`.github/workflows/ci.yml`) checks formatting and Clippy, runs the tests and
builds the app on Windows, Linux and macOS for every push (all branches) and pull request.
The packaged builds are attached to each run as artifacts.

To publish a release:

1. Add a `## vX.Y.Z – YYYY-MM-DD` section to [`CHANGELOG.md`](CHANGELOG.md) and bump
   `version` in `wled-scanner-rs/Cargo.toml`.
2. Commit, then tag and push: `git tag -a vX.Y.Z -m "WLED Scanner vX.Y.Z" && git push origin main vX.Y.Z`

The CI then creates the GitHub release with the three packages. The release note is the
version's changelog section plus the download table from `.github/release-notes-footer.md`
(preview it with `.github/scripts/release-notes.sh vX.Y.Z`). A tag without a changelog
section fails the CI before anything is published.
